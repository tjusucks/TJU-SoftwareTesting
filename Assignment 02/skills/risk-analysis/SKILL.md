# Risk Analysis

## Overview

This skill evaluates structured requirements and determines testing priorities using a risk-based testing approach.

The skill consumes requirement specifications produced by the Requirement Structuring skill and generates risk analysis artifacts for test planning and downstream test design.

The design follows ISTQB risk-based testing principles.

**The risk analysis workflow handles:**

- Read structured requirements.
- Identify requirement-level risks.
- Analyze likelihood and impact.
- Calculate risk scores.
- Assign High / Medium / Low priorities.
- Produce risk rationale and recommendations.
- Generate machine-readable risk outputs.
- Support downstream test planning and black-box design.

**Primary outputs:**

- Risk inventory.
- Risk scores.
- Risk priorities.
- Risk rationale.
- Requirement-to-risk mappings.
- Risk-based testing recommendations.

---

## When to Use This Skill

Use this skill when:

- Structured requirements have already been generated.
- Risk analysis is required before test planning.
- Requirement priorities must be determined.
- Test effort allocation decisions are needed.
- A risk report is required.

Do not use this skill for:

- Requirement extraction.
- Requirement modification.
- Black-box test generation.
- White-box modeling.
- Test execution.
- Cost estimation.
- Final test-plan ownership.

## Risk Scoring Model

### Impact Scale

| Score | Meaning         |
| ----- | --------------- |
| 1     | Minimal impact  |
| 2     | Low impact      |
| 3     | Moderate impact |
| 4     | Major impact    |
| 5     | Critical impact |

### Likelihood Scale

| Score | Meaning     |
| ----- | ----------- |
| 1     | Rare        |
| 2     | Unlikely    |
| 3     | Possible    |
| 4     | Likely      |
| 5     | Very likely |

### Risk Formula

Risk Score = Impact × Likelihood(Range: 1 - 25)

### Priority Mapping

| Risk Score | Priority |
| ---------- | -------- |
| 15-25      | High     |
| 8-14       | Medium   |
| 1-7        | Low      |

## Required Output Contract

Machine output must follow:

- `schemas/risk-analysis.schema.json`

### Output Directory

```
outputs/risk-analysis/{feature_id}/
├── risk-analysis.json
├── report.md
└── revision_log.json   # present only if revisions were applied
```

### Example Output Structure

```json
{
  "schema_version": "1.0",
  "feature_id": "article-lifecycle",
  "items": [
    {
      "risk_id": "RK1",
      "requirement_id": "R1",
      "impact": 5,
      "likelihood": 4,
      "risk_score": 20,
      "priority": "High",
      "rationale": "..."
    }
  ]
}
```

### Human-readable Report Content

report.md should include:

- Feature overview
- Requirement inventory
- Risk summary
- High-risk requirements
- Medium-risk requirements
- Low-risk requirements
- Risk scoring rationale
- Open questions and assumptions
- Recommendations for test planning

requirement_id -> risk_id
